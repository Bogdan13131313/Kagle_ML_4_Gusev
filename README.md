# Ранжирование поисковых результатов

Я решал задачу ранжирования русскоязычных фрагментов по запросу. Итоговая отправка получила **0,959485 NDCG@10 на Public Leaderboard**. Финальная модель: Qwen3-Reranker-4B + Jina Reranker v3.5 + CatBoostRanker.

Данные — [AMML Ranking Competition 2026](https://www.kaggle.com/competitions/amml-ranking-competition-2026).

## 1. Проверил данные

В train — 31 530 пар и 3 042 запроса, в test — 13 507 пар и 1 305 запросов. Для каждого запроса нужно оценить всех предложенных кандидатов.

Я проверил пропуски, повторы и форматы полей. Исправил явные ошибки кодировки, HTML и невидимые символы. Пустые заголовки сохранил как пропуски. Числа, отрицания и пунктуацию на входе нейросетей оставил. Для некорректных числовых метаданных добавил отдельные признаки. Идентификаторы использовал для группировки и выравнивания строк.

## 2. Настроил валидацию

Чтобы один документ не оказался одновременно в обучении и проверке, объединил запросы с общими `document_id` или одинаковым нормализованным текстом в компоненты. Разделил компоненты на пять фолдов. Пересечения по статьям при этом возможны.

Четыре фолда, 2 434 запроса, использовал для сравнения вариантов. Каждый раз обучался на трёх и проверялся на четвёртом. OOF ниже — объединённые предсказания этих четырёх проверок. TF-IDF и BM25 в каждом запуске обучал только на тренировочной части.

Пятый фолд, 608 запросов, оставил для проверки выбранной конфигурации.

NDCG@10 считал отдельно для каждого запроса и затем усреднял. Идеальный порядок строил по всем его кандидатам. При равных прогнозах сортировал по строковому `id`, при нулевом IDCG ставил 0.

## 3. Получил исходную модель

Начал с простых признаков длины и позиции, затем рассчитал оценки Qwen3-Reranker-4B. Длинные тексты разбивал на окна по 1 024 токена с перекрытием 128, чтобы не терять конец фрагмента. Основной оценкой брал максимум разности логитов `yes` и `no`; характеристики остальных окон добавил в признаки.

После этого обучил CatBoost поправке к Qwen. Проверил глубину 4/6, 300/600 деревьев и масштаб исходных оценок.

## 4. Проверил улучшения

Сравнил регуляризацию, функции потерь, дополнительные признаки и усреднение моделей. TF-IDF и BM25 добавил, чтобы учитывать буквальные совпадения слов там, где семантической оценки недостаточно. Все значения таблицы относятся к одним 2 434 запросам.

| Вариант | OOF NDCG@10 | Что решил |
| --- | ---: | --- |
| Равные оценки всех кандидатов | 0,572213 | Использовал как начальный ориентир |
| Короткие фрагменты выше длинных | 0,659060 | Длину оставил дополнительным признаком |
| Qwen 4B | 0,930917 | Взял за семантическую основу |
| Qwen 4B + CatBoost | 0,935350 | Сохранил обучаемую поправку |

Отдельно проверил инструкцию Qwen с акцентом на прямой ответ. На полном development получил 0,935690 без обученной поправки. Завершённого улучшения итогового обучаемого решения этот опыт не дал.

## 5. Сравнил более сильные реранкеры

На 512 полных запросах Qwen 8B получил 0,937307, а Jina — 0,953822. Продолжил работу с Jina.

Jina оценивает всех кандидатов запроса совместно. Я заметил влияние порядка и сделал два прохода: по `id` по возрастанию и по убыванию. Затем усреднил оценки. Кандидатов не удалял и тексты дополнительно не сокращал.

Также пробовал дообучение нейросетей. Ранний BGE улучшился с 0,927617 до 0,939715 на отдельном разбиении из 456 запросов. Эти числа с основной OOF-таблицей не сравнивал, веса BGE в финал не переносил. Пилот Qwen остановился после 20 шагов; итоговое качество на валидации не было измерено. Для финального решения оставил фиксированные нейросетевые веса и обучение CatBoost на данных соревнования.

## 6. Выбрал финальную схему

Добавил оценки Jina к признакам Qwen и сравнил, относительно какой модели лучше обучать поправку CatBoost.

| Вариант | OOF NDCG@10, 2 434 запроса |
| --- | ---: |
| Qwen + CatBoost + TF-IDF/BM25 | 0,936205 |
| Jina без обученной поправки | 0,956957 |
| Qwen и Jina в признаках, поправка к Qwen | 0,962604 |
| Qwen и Jina в признаках, поправка к Jina | **0,963160** |

Выбрал последний вариант. На отложенных 608 запросах получил **0,967511**, затем обучил итоговую модель на всём train. Отправка на Kaggle получила **0,959485** на Public. Это три разные оценки: OOF, отложенная выборка и Public.

## 7. Зафиксировал финальный пайплайн

1. Очищаю исходные тексты и разбираю метаданные.
2. Рассчитываю оценки Qwen по окнам полного текста.
3. Рассчитываю оценки Jina в двух порядках кандидатов.
4. Обучаю словари TF-IDF и статистики BM25 только на документах train.
5. Собираю 115 признаков: лексику, метаданные, текстовую статистику и оценки реранкеров.
6. На всём train обучаю CatBoost: `PairLogit`, 600 деревьев, глубина 6, `learning_rate=0.03`, `l2_leaf_reg=5`, `seed=42`.
7. Сохраняю прогноз для каждой строки test в порядке `sample_submission.csv`.

Для пар «релевантный — нерелевантный» суммарный вес одного запроса равен 1, чтобы запросы с большим числом пар не доминировали. Итоговая оценка:

```text
prediction = 10 × средняя оценка Jina + поправка CatBoost
```

Версии пакетов и ревизии нейросетевых весов зафиксировал. Для обучения использовал только метки train соревнования.

## 8. Локальный запуск

В репозитории три файла:

| Файл | Содержимое |
| --- | --- |
| `solution.ipynb` | Финальная подготовка, обучение и инференс |
| `requirements.txt` | Пакеты с фиксированными версиями |
| `README.md` | Последовательность экспериментов и выводы |

Окружение для этой версии: **Windows 10/11 x64, CPU с AVX2, Python 3.13 x64 и NVIDIA GPU с драйвером для CUDA 13.0**. Исходный нейросетевой расчёт выполнял на двух T4 по 16 ГБ. На одной видеокарте части данных обрабатываются последовательно.

Словари TF-IDF рассчитываются в отдельном процессе с отключённым AVX-512. Настройка применяется автоматически. Для Jina предусмотрен резервный расчёт attention частями, если экономный CUDA-режим недоступен; все кандидаты и тексты сохраняются.

1. Положить исходные `train.csv`, `test.csv`, `sample_submission.csv` в папку `data` рядом с ноутбуком.
2. Открыть PowerShell в папке с тремя файлами. Команда `py -3.13 --version` должна показывать Python 3.13.x.
3. Создать окружение, установить пакеты и открыть Jupyter:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m ipykernel install --user --name amml-windows --display-name "AMML (Windows)"
.\.venv\Scripts\python.exe -m notebook solution.ipynb
```

4. Выбрать ядро **AMML (Windows)** и выполнить **Restart Kernel and Run All Cells**. Первый запуск требует интернет для загрузки весов. Qwen использует отдельные `transformers==4.51.3` и `tokenizers==0.21.4`; ноутбук устанавливает их автоматически.
5. Забрать `output/submission.csv`. Модель и промежуточные расчёты создаются в `output/` автоматически. Для первого запуска нужны три файла репозитория и CSV соревнования.

В ноутбуке выполняется финальная конфигурация Qwen + Jina + CatBoost. История экспериментов приведена выше.

Результат **0,959485** относится к исходной отправке. Исходный контрольный CPU-прогон на Linux совпал с ней побайтно. Проверил наличие Windows-колёс для 125 закреплённых пакетов и согласованность их зависимостей. Полный прогон и совпадение результата на Windows здесь не проверялись.
